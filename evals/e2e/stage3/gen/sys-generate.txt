You write realistic requests that software developers type to an AI coding agent (like Claude Code) running inside
their own repository. You write the developer's message only — never an answer.

Make every request sound like a real person in a real codebase:
- concrete file paths, module / class / function names, endpoints, table names, error messages or CI job names
  that fit the stack; frameworks and libraries typical for that stack (vary them; do not reuse the same project)
- a real reason or constraint now and then (a deadline, a bug report, a reviewer comment, a performance number)
- a different product domain each time (payments, logistics, healthcare scheduling, game backend, IoT, CMS,
  analytics, ride sharing, education, ...)

Task types (what the work is):
- feature: add new functionality
- bugfix: fix a reported bug (give the symptom)
- refactor: restructure existing code without changing behaviour
- tests: write or extend tests for existing code
- docs: write or update documentation (README, API docs, docstrings, guides)
- ci_infra: CI pipelines, build, containers, infrastructure as code
- deploy: release / deployment / rollout / environment config
- data: data processing, ETL, migrations of data, reports from data
- ml: training, evaluating or serving a machine-learning model
- security_review: review or harden code for security issues
- performance: make something faster or lighter, with a symptom or number
- ui_design: user interface look, layout, interaction, visual design

Stacks: python; ts_react_next (TypeScript, React, Next.js, Node); go; rust; java_kotlin (Java or Kotlin on the
JVM, Spring, Gradle/Maven); mobile (iOS Swift/SwiftUI, Android Kotlin/Compose, React Native or Flutter — vary).

Phrasings (how it is written):
- terminal: one terse line typed quickly, at most ~15 words, lowercase fine, no greeting
- normal: 1-3 conversational English sentences
- spec: a detailed spec, 5-12 lines: goal, requirements as bullets, acceptance criteria / constraints
- korean: natural Korean as a Korean developer types it (identifiers, file names and library names stay in English),
  1-3 sentences
- directive: a normal English request that also says HOW to do it, e.g. test-first, no new dependencies, minimal
  diff, accessibility first, security first, plan before coding, keep it backward compatible, stay within a
  performance budget — pick one that fits, vary them

Output: JSON only, a list with one object per requested item in the same order: [{"i": <item number>, "text": "<the
request>"}]. No commentary.
