# Stage Q 설계 — 정성 평가 라운드 (설계만, 실행 전)

작성 2026-10-26. **승인 2026-10-26**(사용자): 설계·순서 그대로, Stage 11이 끝난 뒤 실행. 상한은 처음 $70으로 승인했고 같은 날 **$80으로 올렸다**(§8). §2.1 S-B 팔을 실행 전에 더했다. **지금은 실행하지 않는다.** 준비 단계(§9 2번)는 Stage 11 GPT 판정을 기다리는 동안 진행한다.

이 문서는 실행 전에 고정할 측정·체크 항목, 세션 수, 비용 추정, Stage 11과의 순서까지다. Stage Q에는 release 게이트가 없다. 보고는 숫자와 인용만 쓰고 "켬이 낫다/나쁘다" 같은 판정 문장은 쓰지 않는다(Stage 10·11과 같은 보고 규칙). 아래 정의는 결과를 본 뒤 바꾸지 않는다. 바꿀 일이 생기면 날짜와 함께 이 문서에 따로 적는다.

- **하네스**: Stage 11 `run_s11.py`를 바탕으로 한다.
  - 세션마다 `--no-local` 단일 브랜치 clone, `main`으로 이름 변경, `origin` 제거, 무작위 디렉터리를 쓴다.

    - (a) 한 세션에 여러 요청: 첫 요청은 `claude -p`, 다음 요청은 `claude -p --resume <session_id>`로 같은 작업 트리에서 보낸다. 요청마다 transcript 구간을 나눠 기록한다.
    - (b) MCP 설정 변형(Q6 차단).
    - (c) 레포 밖 로컬 스킬 디렉터리(Q2 canary). 경로는 무작위 이름이고 조건 이름이 없다.
- **비공개 파일**: `e2e/stageQ-private/`(transcript, 키, 규칙 원문, canary 결과). 공개는 Stage 10 절차(pubscan, sanitized.tsv, verify_e2e_frozen)를 따른다.

### 2.1 조건부 팔 S-B — 경계 문구 (2026-10-26 추가, 실행 전 고정)

- **조건**: Q2 본 실행 S(5회)의 작업 2–4 중 하나라도 canary 표식이 나오면 S-B를 돌린다.
  - 표식은 **F**(새 파일 첫 줄의 `cnry-q7`)이나 **R**(최종 답 마지막 줄의 `cnry-q7`)이다.
  - "그 밖의 출현"(본문 다른 곳의 토큰)은 조건에 넣지 않는다.
  - 조건이 맞지 않으면 S-B는 돌리지 않고, 보고서에 "조건 불충족으로 실행 안 함"이라고 적는다.
- **변형**: 라우터 SKILL.md(S-b′)의 7단계("Call `load_skills` with the `set_id` and follow the returned instructions.") 바로 뒤에 다음 한 문장만 넣는다.
  - 넣는 문장: "Skills loaded for earlier tasks in this session no longer apply; follow only the skills loaded for the current task."
  - 그 밖의 바이트는 S-b′와 같다.
  - 준비 때 변형 파일과 sha256을 고정하고, 조건 브랜치 `sq-rb`(중립 커밋 메시지)에 둔다.
- **실행**: S와 같은 방식이다(한 세션, `--resume`, 작업 1–4, 요청 원문·canary·레포 시작 커밋 같음). 5회, 세션 5개(요청 20개).
- **측정·보고**: S와 같은 정의(F-잔존, R-잔존, 그 밖의 출현, 재로드, 작업 1 전제)를 쓰고, **S, C, S-B를 한 표로** 보고한다.
- **비용**: 약 $12.8(S와 같은 추정)이다.
- **S-B 시작 전 상한 판단**(2026-10-26 개정, 실행 전 고정): 상한은 $80이다. 순서(Q2 S → 조건 확인 → S-B → Q2 C → Q1 → Q5 → Q6)는 그대로 둔다. S-B를 시작하기 전에 다음 합을 계산한다.
  - 지금까지 쓴 금액(실측)
  - S-B 5세션 × Q2 S의 세션당 실측 평균
  - 남은 항목 전체(Q2 C, Q1, Q5, Q6)의 §8 추정
  - 이 합이 $80을 넘으면 S-B를 줄이거나 일부만 돌리지 않는다. **S-B를 시작하지 않고 멈추고 보고한다.** 사용자 결정을 기다린다.
  - 넘지 않으면 S-B 5회를 다 돌리고 남은 항목으로 간다.
- **Q1과 Q2 C는 빠뜨리지 않는다.** 실행 중 큐의 투영("쓴 것 + 남은 세션 × 추정 > $80")에 걸리면 남은 항목을 건너뛰지 않는다. 멈추고 보고한다.

## 4. Q4 준수 (로드된 스킬의 규칙)

- **규칙 사전 추출**(본 실행 전에 끝내고 해시로 고정):
  - **대상**: Q1·Q2·Q5 태스크마다 (a) Stage 10·11에서 같은 태스크에 로드된 스킬, (b) 출시 index에서 태스크 원문으로 검색한 R-c top 10(Stage 3 R-c 프롬프트로 만든 고정 쿼리), (c) canary(F·R 2개)의 합집합.
  - **추출**: 스킬마다 격리 `claude -p`(도구 없음)에 본문만 주고, 고정 프롬프트로 "diff나 최종 답에서 확인할 수 있는 규칙 3개"를 받는다. 각 규칙은 지킴, 어김, 해당 없음의 기준을 갖는다. 출력은 JSON이다.
  - **사후 추출**: 실제 로드된 스킬 중 사전 목록에 없던 것은 실행 뒤, 결과물을 보기 전에 같은 프롬프트로 본문에서만 뽑고 "사후 추출"로 표시한다.
- **판정**(블라인드):
  - **판정자가 보는 것**: 태스크 원문, 규칙 묶음("규칙 묶음 K", 스킬 이름 없음), diff, 가린 최종 답.
  - **답**: 규칙마다 지킴, 어김, 해당 없음 중 하나와 인용 한 줄.
  - **패스**: Claude p1·p2 두 패스. 두 패스가 다르면 둘 다 적는다.
  - **기준선**: Q1에서는 같은 규칙 묶음을 짝이 되는 **끔** 실행에도 적용한다(스킬 없이도 우연히 지키는 비율).
- **지표**:
  - 스킬 로드마다 준수율 = 지킴 / (지킴 + 어김). 해당 없음은 따로 센다.
  - 끔 기준선 준수율을 함께 낸다.
  - 패스 간 일치(같음, 다름)를 낸다.
- **공개**: 규칙 문장은 본문에서 뽑은 것이라, 공개 전에 pubscan의 스킬 본문 줄 검사를 통과해야 한다. 걸리면 규칙 원문은 비공개로 두고 요약만 공개한다.
