## 1. 배치 효과 검사

60태스크 × (새 레코드 5행 + 기존 후보 5행)을 태스크마다 한 목록에 섞어, 같은 2b 프롬프트(Opus)로 다시 채점했다. 600행, 누락 0이다.

| 행 | n | 완전 일치 | ±1 | 관련 여부 κ | 원래 ≥2 → 재채점 ≥2 | 평균 등급 원래 → 재채점 | 차이 (재채점 − 원래) |
|---|---:|---:|---:|---:|---|---|---:|
| **새 레코드** (§5 채점) | 300 | 0.910 | 1.000 | 0.885 | 29 → 29 | 0.323 → 0.367 | **+0.043** |
| **기존 후보** | 300 | 0.917 | 1.000 | 0.830 | 14 → 17 | 0.223 → 0.280 | **+0.057** |
| 기존 · v5-ss 본채점 | 42 | 0.833 | 1.000 | 0.725 | 3 → 5 | 0.452 → 0.524 | +0.071 |

- **새 레코드 − 기존 후보의 평균 차이 변화**: −0.013. 행 단위 부트스트랩 95% 구간은 [−0.06, 0.03]으로 0을 포함한다.
- **§12-1 해석 규칙**(새 레코드 쪽만 내려가면 배치 효과)에 따르면 **배치 효과는 보이지 않는다.** 두 쪽 모두 재채점에서 평균이 조금 올랐고, 새 레코드 쪽만 내려간 것은 없다.
- **등급 분포**(0/1/2/3):
  - 새 레코드: 235/36/26/3 → 221/50/27/2
  - 기존: 247/39/14/0 → 233/50/17/0
- **한계**:
  - 무작위 행이라 등급 ≥2가 적다(새 29, 기존 14). 관련 여부 κ는 이 작은 수에 기댄다.
  - 같은 모델(Opus)의 재채점이다. 모델 자체의 치우침은 이 검사로 알 수 없다. 그것은 GPT 교차 라벨(§2)의 몫이다.

## 2. GPT 교차 라벨 파일

- **파일**: `blind-run-b-60.jsonl`, 60태스크·724행. 필드는 task_id, task_text, candidate_id, title, summary다. 출처·이전 등급은 넣지 않았다.
- **태스크**: 380태스크 모두 스테이징 top-10에 새 레코드가 1개 이상 있다. 시드 `s9b-gpt60`, 작업종류 비례로 골랐다(feature 5, bugfix 5, refactor 4, tests 4, docs 4, ci_infra 5, deploy 5, data 4, ml 5, security_review 4, performance 5, ui_design 4, trivial 6).
- **행**:
  - 새 레코드 362행 = 스테이징 top-10의 새 레코드 전부
  - 기존 레코드 362행 = 스테이징 top-10의 기존 레코드 188행 + 기준 index top-10(밀려난 자리) 174행
  - 모든 태스크에서 같은 수를 채웠다.
- **대응표**: `blind-run-b-60-key.json`. 행마다 skill id, 출처, Opus 등급이 있다. Opus 등급이 없는 행은 0이다.
- **GPT 결과가 오면**: `gpt-run-b-60.jsonl`(task_id, candidate_id, grade, process; 724행 전부)을 `stage9/`에 두고 `scripts/s9_gpt_run_b.py`를 실행한다.
  - 일치(완전, ±1, 관련 여부 κ, process κ)를 전체 / 새 레코드 / 기존으로 낸다.
  - 교집합 라벨로 60태스크의 R-c hit@10(기준 대 스테이징)과 S-b′ 관련 로드(기준 3회 대 스테이징 1회)를 다시 계산한다.
  - 파일이 없거나 행이 빠지면 실행을 거부한다.
  - GPT = Opus 사본인 합성 파일로 시험한 결과, κ 1.0이 나왔고 교집합 = Opus로 동작했다. 시험 파일은 지웠다.
- **GPT가 덮는 범위**(미리 계산):
  - 스테이징 top-10 자리 550/600, 기준 index top-10 자리 356/600
  - 스테이징 선택 51/78, 기준 r1 선택 28/64
  - **덮는 범위가 스테이징 쪽이 더 넓다.** 교집합은 관련을 줄이는 방향으로만 작동하므로, 스테이징 쪽 수치가 더 많이 깎일 수 있다.
- **현재 Opus 라벨 기준값**(같은 60태스크): R-c hit@10 기준 0.714(n=42) → 스테이징 0.796(n=54; 기준 분모로는 0.857). S-b′ 관련 로드는 기준 0.714/0.762/0.762, 스테이징 0.889다.

## 3. run-c 예상치 (오프라인: index-staging-2에서 dpearson2699 86개 제외)

`scripts/s9_search_excl.py`로 `index-staging-2`를 읽고 dpearson 레코드를 지운 뒤 R-c를 돌렸다. 남은 레코드는 2,785개, 오류는 0이다.

| | 기준 index | run-b | **run-b − dpearson** |
|---|---:|---:|---:|
| (A) v3 hit@50 / recall@50 (고정 라벨) | 0.930 / 0.808 | 0.859 / 0.643 | **0.845 / 0.624** |
| (A) v5-ss-b hit@50 / recall@50 (고정 라벨) | 0.941 / 0.822 | 0.819 / 0.540 | **0.789 / 0.517** |
| (B) v3 전체 라벨 hit@10 / hit@50 | 0.754 / 0.930 | 0.873 / 0.989 | **0.849 / 0.989** |
| (B) v5-ss-b 전체 라벨 hit@10 / hit@50 | 0.556 / 0.941 | 0.826 / 0.974 | **0.815 / 0.970** |
| top-50의 새 레코드 자리 | – | 10,750 | 11,280 |

- **(A) 고정 라벨**: dpearson을 빼도 통과하지 못한다. 오히려 run-b보다 조금 더 떨어진다.
  - dpearson이 비운 top-50 자리를 다른 새 레코드가 채웠다(새 레코드 자리 10,750 → 11,280).
  - 고정 라벨은 새 레코드를 관련으로 치지 않으므로, 이 값은 미채점 행과 무관하게 확정이다.
- **(B) 전체 라벨 hit@50**: v3 0.989, v5-ss-b 0.970으로 기준선(0.930, 0.941)보다 0.01 넘게 떨어지지 않는다.
  - 이 값은 **하한**이다. dpearson을 빼서 새로 top-50에 들어온 행 중 **2,656개(top-10에서는 440개)가 미채점**이고 무관으로 처리했다.
- **(C)**: S-b′ 선택을 돌리지 않아 계산하지 않았다.
- 따라서 run-c가 이 오프라인 근사와 같다면, §11 판정은 (A) 실패이고 (B) 통과(하한)다. 결과는 **(C)에 달려 있다.**
- 미채점 2,656개를 채점하면 (B)·hit@10을 확정할 수 있다. 예상 비용은 약 $3–4다(호출당 $0.011 + 행당 $0.0010 기준). 요청 범위 밖이라 실행하지 않았다.
- **전제**: 이 근사는 run-c 재빌드에서 dpearson 밖의 레코드가 index-staging-2와 바이트 단위로 같다는 것을 전제한다. 레포 세션의 run-c가 다른 소스·추출을 바꾸면 맞지 않는다.

## 4. GPT 교차 라벨 결과 (2026-10-25, `gpt-run-b-60.jsonl` 724행)

- **실행**: `scripts/s9_gpt_run_b.py`로 `gpt-run-b-60.json`을 만들었다. 방향 분석은 `scripts/s9_gpt_direction.py`로 했고 결과는 `gpt-run-b-60-direction.json`이다. 모델 호출은 없다.
- **행의 출처**: run-b 순위는 12:13Z 빌드의 것이다(`report-9c.md` §1 참고). Opus 등급은 run-b 라벨(`run-b/oracle-v5-ss-b-s9g.jsonl`)이다.

### 4.2 GPT가 새 레코드에서만 Opus보다 짜게 줬는가

| 행 | 평균 Opus → GPT | GPT − Opus | GPT가 낮음 / 높음 | Opus 관련(≥2) 중 GPT가 <2로 내림 | Opus 무관 중 GPT가 ≥2로 올림 |
|---|---|---:|---|---|---|
| **새 레코드** | 0.666 → 0.782 | **+0.116** | 31 / 74 | **13/70 (0.186)** | 20/292 (0.068) |
| **기존 레코드** | 0.439 → 0.743 | **+0.304** | 2 / 102 | **2/43 (0.047)** | 42/319 (0.132) |

- **새 − 기존**:
  - GPT − Opus 차이는 **−0.188**, 행 부트스트랩 95% 구간 [−0.265, −0.108]이다.
  - 관련 강등률 차이는 **+0.139**, 95% 구간 [0.031, 0.247]이다.
- **답**: 기존 레코드와 견주면 GPT는 새 레코드에 더 짜다. 두 구간 모두 0을 포함하지 않는다.
  - GPT는 기존 레코드를 Opus보다 크게 올려 줬다(+0.304, 강등 2건).
  - 새 레코드에서는 덜 올려 줬다(+0.116). Opus가 관련으로 본 새 레코드 70개 중 13개를 2 미만으로 내렸다.
  - 다시 말해 **Opus는 GPT 기준으로 새 레코드를 상대적으로 후하게 매겼다.**
  - 다만 절대값으로는 GPT도 새 레코드를 Opus보다 높게 봤다(평균 +0.116, ≥2는 70 → 77). GPT가 새 레코드를 Opus보다 짜게 준 것은 아니다.

### 4.3 이득이 채점 편향이었는가 — 교집합 라벨로 다시 계산 (60태스크)

교집합 라벨: GPT가 본 행은 Opus ≥2 **그리고** GPT ≥2일 때만 관련이다. GPT가 보지 않은 행은 Opus 등급을 그대로 쓴다.

| | Opus 라벨 | 교집합 라벨 |
|---|---:|---:|
| 관련 태스크 수 (기준 / 스테이징) | 42 / 54 | 42 / 53 |
| R-c hit@10 기준 index | 0.714 | 0.690 |
| R-c hit@10 스테이징 (기준 분모 42) | 0.857 | 0.833 |
| R-c hit@10 스테이징 (각자 분모) | 0.796 | 0.774 |
| **hit@10 이득** (스테이징 − 기준, 기준 분모) | **+0.143** | **+0.143** |
| S-b′ 관련 로드 기준 r1–r3 | 0.714 / 0.762 / 0.762 | 0.714 / 0.762 / 0.762 |
| S-b′ 관련 로드 스테이징 | 0.889 | 0.887 |

- **교집합으로 바꿔도 이득은 그대로다.**
  - hit@10 이득은 +0.143 → +0.143이다.
  - S-b′ 관련 로드는 스테이징 0.889 → 0.887이고, 기준 범위는 0.714–0.762다.
  - GPT가 내린 새 레코드 13행은 9태스크에 걸쳐 있다(그중 expect_none 1).
  - 적중 수 변화:
    - 기준 분모 42에서 스테이징 hit@10 적중이 36 → 35, 기준 index 적중이 30 → 29로 둘 다 1개씩 줄었다.
    - 각자 분모에서는 스테이징 43/54 → 41/53이다(관련 태스크 하나가 분모에서 빠짐).
- **GPT가 덮은 범위**: 스테이징 top-10 자리 550/600, 기준 top-10 356/600, 스테이징 선택 51/78, 기준 r1 선택 28/64. 교집합은 관련을 줄이는 쪽으로만 작동하므로, 덮는 범위가 넓은 스테이징 쪽이 더 많이 깎일 수 있는 조건이다. 그런데도 이득이 남았다.
- **한계**:
  - 60태스크에서 관련 태스크는 42/54로 작다.
  - 교집합만 계산했다. GPT 라벨 단독 계산은 하지 않았다.
  - GPT는 기존 레코드를 크게 올려 준다(무관 → ≥2가 42건). GPT 단독 라벨이라면 기준 index 쪽 수치도 함께 오를 것이다.
